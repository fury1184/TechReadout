TechReadOut v3.8.2 — Inventory search box + CPU-Monkey lookup fix +
                      socket normalization (display fix + real ingestion fix)
================================================================

Files in this patch (paths relative to repo root):

  app/routes/main.py                inventory_list() and inventory_export()
                                     both gained a `q` query param. When
                                     present, results are filtered (case-
                                     insensitive partial match) against
                                     HardwareSpec.model, HardwareSpec.
                                     manufacturer, Inventory.custom_name, and
                                     Inventory.custom_manufacturer via an
                                     outerjoin — covers both catalog and
                                     manually-entered custom items. ANDs with
                                     the existing Component Type / Status /
                                     Assignment filters rather than replacing
                                     them; CSV export now respects an active
                                     search the same way it already respects
                                     the other filters. inventory_list() also
                                     passes current_query=q to the template so
                                     the entered value survives reloads.

  app/templates/inventory/list.html Adds a full-width Search input as its own
                                     row at the top of the existing filter
                                     <form>, above Component Type / Status /
                                     Assignment, so it submits and combines
                                     with them automatically. Placeholder
                                     example text ("i5, 3060, ASUS") hints at
                                     partial-match behavior.

  app/scrapers/lookup.py            Fixed _cpu_monkey_slug() building a
                                     malformed CPU-Monkey URL (duplicate
                                     "intel", e.g. cpu-intel_core_intel_i5_
                                     2500k instead of cpu-intel_core_i5_2500k)
                                     whenever the incoming query already
                                     contained a leading "intel " token — e.g.
                                     a combined manufacturer+model query like
                                     "intel i5-2500k" from the Add Item form's
                                     manufacturer field. The family-prefix
                                     inserts ("core "/"xeon ") ran before the
                                     startswith('intel ') check, pushing an
                                     existing "intel " out of position and
                                     causing it to be re-added a second time.
                                     Same bug class would have hit Xeon
                                     queries too (e.g. "intel e5-2680v4" ->
                                     "intel xeon intel e5-2680v4"). Fix strips
                                     any leading "intel" up front and re-adds
                                     it exactly once after the family-prefix
                                     logic runs. Root-caused via a live
                                     "i5-2500K" lookup that missed Intel ARK
                                     (separate/unrelated miss) and then hit
                                     this bug on the CPU-Monkey fallback,
                                     returning a 404.

  app/routes/stats.py                - Added "LGA2011": "LGA 2011" to
                                       VALUE_ALIASES for cpu_socket and
                                       mobo_socket (spacing-only duplicate
                                       rows on the /stats BY SOCKET table).
                                     - Added "LGA1151": "LGA 1151" to
                                       mobo_socket (same spacing issue).
                                       "LGA 1151 (300 Series)" is left
                                       unmerged on purpose — it's a real
                                       electrical-spec distinction (300-
                                       series boards aren't compatible with
                                       earlier Skylake/Kaby Lake LGA1151
                                       boards despite the same physical
                                       socket), not a data-entry variant.
                                     - _normalize_value() alias matching was
                                       case-sensitive, so "LGA2011-v3"
                                       (lowercase v) wasn't matching the
                                       already-mapped "LGA2011-V3" and stayed
                                       as its own row. Added a case-
                                       insensitive fallback so future casing
                                       variants don't each need their own
                                       explicit dict entry.
                                     - Added a new mobo_chipset alias group
                                       (field had none before): "Intel
                                       Z390"->"Z390", "Intel X99"->"X99",
                                       "Intel X79"->"X79", "Intel Z370"->
                                       "Z370" — the BY CHIPSET table was
                                       showing prefixed/unprefixed forms of
                                       the same chipset as separate rows
                                       (Z390: 3 + Intel Z390: 2, X99: 1 +
                                       Intel X99: 1). All display-only; raw
                                       DB values untouched.

  app/name_normalization.py         NEW function normalize_socket(). The
                                     real ingestion-time fix behind the
                                     stats.py display patch above — see
                                     BACKLOG note in stats.py. Canonicalizes
                                     LGA socket spacing/dash/casing variants
                                     (LGA1151/LGA 1151 -> "LGA 1151";
                                     LGA2011-V3/LGA2011-v3/LGA 2011-v3 ->
                                     "LGA 2011-3"). Preserves meaningful
                                     suffixes like "(300 Series)" — a real
                                     electrical-spec distinction, not a
                                     formatting variant. Non-LGA sockets
                                     (AM4, AM5, sTRX4, etc.) pass through
                                     unchanged (whitespace collapsed only) —
                                     no issues seen there yet, so left alone
                                     rather than guessed at.

  app/models.py                     Added a before_insert/before_update
                                     SQLAlchemy event listener on
                                     HardwareSpec that runs
                                     normalize_socket() on cpu_socket and
                                     mobo_socket automatically on every
                                     save. Single choke point — covers
                                     scraper results, seed import, the
                                     manual add/edit form, and backup/JSON
                                     import in one place, so no individual
                                     call site needs its own normalization
                                     logic and none can forget to add it
                                     later. NOTE: only normalizes new
                                     writes going forward — existing rows
                                     are NOT retroactively cleaned up by
                                     this alone (see "Not included" below).

  app/version.py                    APP_VERSION bumped 3.7.0 -> 3.8.2
                                     (3.8.0 search feature + 3.8.1 lookup
                                     fix + 3.8.1 socket alias display fix +
                                     3.8.2 socket ingestion-normalization
                                     fix, combined into a single release
                                     since 3.8.x had not yet been deployed).

To apply: copy all files above over the matching paths in your working tree.
No rebuild needed — the ./app bind mount picks up route/template changes,
and Flask's debug reloader restarts the dev server automatically on save.

Not included in this patch: no changes to the Intel ARK search step itself
(the miss seen in testing appears to be a separate ARK search-result/parsing
issue, not yet diagnosed); no retroactive re-lookup of any inventory items
that were previously imported with unresolved specs due to the CPU-Monkey
bug; and no backfill of existing messy cpu_socket/mobo_socket values already
in the database — normalize_socket() only fires on new inserts/updates, so
existing rows still rely on the stats.py VALUE_ALIASES display patch until a
backfill (one-off script, or folded into the existing /maintenance/
normalize-names page) is built — deferred pending a decision on which.
